# 指标口径定义（Phase 0）

- 版本：1.0（2026-11-16）
- 适用范围：本仓库全部页面展示指标 + 已规划待实现指标
- 原则：**每个数字都必须能被追问三件事——从哪来、怎么算、什么时候的**。答不上的指标不应出现在页面上。

---

## 1. 通用约定

### 1.1 数据类型

| 值 | 含义 | 判定标准 |
|---|---|---|
| `real` | 外部数据源直接返回 | 能指出具体接口与请求参数 |
| `derived` | 基于 real 数据按明确公式计算 | 公式可复现，输入可追溯 |
| `estimated` | 明确估算 | 必须写明假设与误差范围 |
| `mock` | 模拟数据 | 仅限开发/测试，不得出现在生产展示 |
| `unavailable` | 无法获得 | 必须说明需要什么权限才能获得 |

### 1.2 时间

- 存储统一 UTC（`ts_utc` / `collected_at`）。
- 展示按浏览器本地时区（当前为 UTC+8）。
- 按日聚合必须显式声明时区；当前所有「日」均为 UTC+8 自然日。
- 环比必须比较**等长且同构**的窗口；窗口不足时返回 `unavailable`，不得用短窗口凑。

### 1.3 缺失处理

- 缺失值不得当 0 参与计算。
- 多分量指标（如风险指数）缺失某分量时，按可用分量重新归一化权重，并返回实际参与的分量列表。
- 可用分量不足（建议 < 2）时整体标记 `unavailable`。

## 2. 已实现的真实指标

### 2.1 当前同时在线人数（CCU）

| 项 | 内容 |
|---|---|
| 定义 | 某一时刻 Steam 上正在运行该游戏的玩家数 |
| 接口 | `ISteamUserStats/GetNumberOfCurrentPlayers/v1?appid={id}` |
| 返回字段 | `response.player_count` |
| `data_type` | `real` |
| 采集频率 | 线上每小时（CI）；本地 5 分钟（SQLite，仅分析用） |
| 存储 | `data` 分支 `steam-ccu.json`（4 款，窗口 72h）；本地 `steam.db` |
| 局限 | **不等于 DAU**；不含离线玩家；上游有约 647 秒 CDN 缓存，必须加穿透参数 |

采集器已处理：`_=<毫秒时间戳>` + `Cache-Control: no-cache`。不加则采到水平直线。

### 2.2 四款合计在线

| 项 | 内容 |
|---|---|
| 定义 | 选中游戏集合内，各游戏最新一次 CCU 之和 |
| 公式 | `Σ latest_ccu[g]`，g ∈ {1203220, 578080, 230410, 238960} |
| `data_type` | `derived` |
| 局限 | **加总只用于 KPI 头条展示，不用于趋势分析**。各游戏体量差 12 倍，加总会被最大者主导 |

环比 = `(Σlatest − Σfirst) / Σfirst`，其中 `first` 为各游戏窗口内首个采样点。窗口不足 2 点时环比返回 `unavailable`。

### 2.3 在线人数指数（归一化）

| 项 | 内容 |
|---|---|
| 定义 | 各游戏以自身窗口均值为 100 的指数化序列 |
| 公式 | `index(t) = ccu(t) / mean(ccu, 窗口) × 100` |
| `data_type` | `derived` |
| 用途 | 横向比较**节奏**（谁在晚间爬得更陡），不比较体量 |
| 局限 | 指数不代表绝对规模；均值随窗口滑动，历史点位的指数值会变 |

### 2.4 成就完成率

| 项 | 内容 |
|---|---|
| 定义 | 全量拥有该游戏的玩家中，解锁该成就的百分比 |
| 接口 | `ISteamUserStats/GetGlobalAchievementPercentagesForApp/v2?gameid={id}` |
| `data_type` | `real` |
| 采集频率 | 线上每次运行（变化极慢，本地 12 小时节流） |
| 局限 | 无时间维度；无解锁先后顺序（本仓库按完成率降序近似推进顺序）；**不等于留存率** |

### 2.5 漏斗跨度

| 项 | 内容 |
|---|---|
| 定义 | 最高完成率与最低完成率之差 |
| 公式 | `span = max(percent) − min(percent)` |
| `data_type` | `derived` |
| 用途 | 衡量「推进到底的玩家比例」的衰减幅度 |
| 局限 | 受成就数量影响（193 个成就的游戏天然跨度大），跨游戏比较需注明成就数 |

当前实测：永劫无间 63.2pp / PUBG 64.0pp / Warframe 64.4pp / Path of Exile 47.4pp。

## 4. Phase 2–4 将新增的真实指标

### 4.1 评论投票类（`real`）

| 指标 | 公式 | 分母 |
|---|---|---|
| 推荐率 | `count(voted_up=true) / count(有效投票评论)` | 明确到窗口 + 语言 |
| 不推荐率 | `count(voted_up=false) / 同上` | 同上 |
| 评论新增量 | `count(timestamp_created ∈ 窗口)` | — |
| 评论更新量 | `count(timestamp_updated ∈ 窗口 且 > created)` | — |

**必须与样本量同时展示**，例如「负面 34.2%（n=1,284）」。百分比脱离样本量是无意义的。

### 4.2 情感类（`derived`）

| 指标 | 定义 |
|---|---|
| 情感分布 | `positive / neutral / negative / unknown` 四类占比 |
| 分母 | **近 N 天已成功分类的评论数**（不含 unknown），且必须显式说明 |
| 置信度 | 每条评论的模型置信度，低于阈值归 `unknown` |
| 模型版本 | `model_name` + `model_version`，用于复现 |

`voted_up` 与模型情感**不得混用**：前者是玩家点按钮的投票，后者是文本分类结果，二者会系统性偏离。

### 4.3 主题类（`derived`）

| 指标 | 定义 |
|---|---|
| 主题占比 | 该主题评论数 / 窗口内已分类评论数 |
| 主题环比 | `(本期 − 上期) / 上期`；上期为 0 时返回 `new`，不返回无穷大 |
| 热点 | 主题占比 × 环比增幅 × 样本充分性，三者的组合判定 |

主题必须可追溯到具体评论 ID，摘要不得由 LLM 编造。

### 4.4 游戏级公开信号风险指数（`derived`）

```
risk = 0.35N + 0.30G + 0.20C + 0.15A
```

| 分量 | 定义 | 取值范围 |
|---|---|---|
| N | 近期负面评论比例 | 0–100 |
| G | 负面评论增长信号 | 0–100 |
| C | 负面主题集中程度 | 0–100 |
| A | 在线人数异常下降信号（可选，需足够基线） | 0–100 |

- 缺失分量按可用权重重新归一化，并返回参与计算的分量列表。
- 输出必须附 `formula_version`、`period`、`sample_size`、`caveats`。
- **不是流失概率**，不做任何准确率宣称。

## 5. 口径红线（禁止出现在任何页面与文档）

| 禁止表述 | 原因 |
|---|---|
| 「活跃玩家 / DAU」指代 CCU | CCU 是瞬时在线，不含离线玩家 |
| 「流失率」「流失概率」 | 需玩家级行为日志 |
| 「D7 留存」「Cohort 留存」 | 需注册时间与登录事件 |
| 「召回率 / 触达率 / 回流人数」 | 需运营事件与归因 |
| 「高危玩家名单」 | 需玩家级画像，且涉及隐私 |
| 「模型情感 = 好评率」 | voted_up 与文本情感是两件事 |
| 「成就完成率 = 留存率」 | 前者是累计快照，无时间维度 |
| 「精准」「实时」等修饰（除非确有毫秒级链路） | 当前采集粒度为 1 小时 |
