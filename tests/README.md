# 冒烟测试

> 冒烟测试只回答一个问题：**这套东西还能不能打开、还能不能用。**
> 它不判断数值对不对、样式好不好看。那些属于回归测试与视觉比对，是另外的层。

## 为什么这个仓库需要它

提交 `ba9e6dd` 把 `stage.setRiskPillars(...)` 写进了错误的 IIFE 作用域，页面加载即抛
`ReferenceError`。后果是地球照常渲染、KPI 照常有数字，**只有 AI 预警面板空着**——
肉眼看上去「差不多是好的」。这个缺陷穿过了 PR #4、#7 两轮合并，并成功部署到 Pages。

部署流水线只证明「文件传上去了」，不证明「页面能用」。这两件事必须分开验证。

## 跑一次

```bash
cd tests
npm install          # 首次；会顺带下载 Chromium headless shell
node smoke.mjs       # 自动在 8099 端口起 http.server，跑完自动关
```

已有服务在跑时复用，不重复启动：

```bash
BASE_URL=http://127.0.0.1:8080 node smoke.mjs
```

退出码即结论：`0` 全绿，`1` 有失败项（可直接用于 CI 卡点）。失败时截图落在 `tests/artifacts/`。

## 判定分四层

| 层 | 检查内容 | 捕获的典型问题 |
|---|---|---|
| **L0 资源层** | 4 个页面均返回 200 | 文件名写错、大小写不一致、资源没提交 |
| **L1 运行层** | 无未捕获异常、无 `console.error`、无失败请求 | **作用域错误、undefined 变量、CDN 断链**——本次缺陷正落在这一层 |
| **L2 结构层** | 关键锚点存在且非空、canvas 已实例化、数据层挂载、无横向溢出 | 渲染函数没跑、容器为空、布局撑破 |
| **L3 交互层** | 时间范围 7/30/90 天切换后文案与 KPI 同步、缺密钥时给出可读提示 | 事件绑定失效、静默失败 |

L1 是最容易被忽略、也最致命的一层。页面「看起来正常」但脚本死在中途，只有控制台知道。

## 自动化覆盖不到，必须人工看的

每次改动首页地球或布局后，花 2 分钟过一遍：

| 项目 | 预期 |
|---|---|
| 地球拖拽 / 滚轮 / 双击 | 旋转、缩放、复位均响应，无卡顿掉帧 |
| 点击地球热点标签 | 相机飞到该区域，信息卡与底部决策链同步切换 |
| 点击区域排行某一行 | 地球转到该区域，其余点位压暗 |
| 策略排行跑马灯 | 悬停暂停；系统开启「减少动效」时改为静态可滚动 |
| 四页导航 | 当前页高亮正确，无「演示」之类残留标记 |
| 1600×1000 与 1366×768 两档 | 无元素重叠、无文字截断 |
| 断网刷新 | 页面完整可用（仓库承诺零 CDN 依赖） |

## 什么时候必须跑

1. 合并到 `dev` 或 `main` 之前——不是之后。
2. 改动 `index.html` / `js/` 下任何脚本之后。
3. 新增外部资源引用之后（L1 会立刻暴露 CDN 断链）。
4. 换机器、换 Python 版本、换浏览器内核之后。

## CI

`.github/workflows/smoke.yml` 在 PR 与 push 到 `main`/`dev` 时运行，失败即阻断。
它和 `deploy.yml` 是两条独立流水线：**冒烟不过，不该有部署**。

## 怎么扩展

`smoke.mjs` 顶部的 `PAGES` 数组即配置表：给某页加一条

```js
['#选择器', 最少元素个数]      // 放 anchors
'#选择器'                     // 放 nonEmpty，要求文本非空
```

选择器要选**由 JS 动态填充**的容器（如 `#warnList`、`#rankList`），不要选静态写死的
HTML —— 静态节点永远存在，断言它等于什么都没测。
